# 轻量对冲控制台稳定性与统计需求

## 目标

在不破坏现有轻量下注核心的前提下，补齐轻量 UI 的执行可视化、计划显示、自动剔除、盈亏统计、进房反馈和手动资源诊断能力，使操作者可以清楚判断系统是否正在稳定对冲。

## 术语

- 发号：统一发号者确认同房、同局、可下注、下注前检查通过后，向各账号 worker 下发真实点击计划。
- 接管：把账号页面交给轻量核心控制，可包含有头到无头切换。
- 有头：浏览器窗口可见，操作者能直接观察。
- 无头：浏览器窗口不可见，由轻量核心后台控制。
- 缺口：计划下注金额减去平台确认接受的实际下注金额。
- 可恢复停止：例如等待下注窗口超时、短暂掉大厅，可继续等待或自动进房。
- 不可恢复停止：例如可用账号不足 3 个、浏览器断开、人工急停，必须停止发号并提示原因。

## 保护边界

以下链路是保护区，除非单独获得明确继续指令，否则本规格不得修改其核心行为：
- 状态采集：余额、局号、状态机、倒计时、房间号、限红。
- 下注定位：筹码坐标、下注区域坐标、坐标刷新时机。
- 下注执行：点击前检查、筹码点击、下注区域点击、确认等待、点击耗时记录。
- 已验证的轻量接管、进房和真实下注函数。

允许的修改范围：
- UI 展示、按钮状态、统计面板、配置保存。
- 轻量核心的参数传递和结果展示接口。
- 对冲计划生成的输入参数和金额拆分策略，但不能破坏点击执行器接口。

## 瘦身原则

- UI 只展示轻量核心已经产出的必要状态，不为展示效果新增高频采集。
- 资源监测只作为人工触发的诊断报告，不进入常驻 UI 和定时后台线程。
- 主界面不保留调试日志面板；只保留最近停止原因、关键错误、计划和执行结果。
- 局号停更优先做“标记异常 + 不参与发号”，不默认触发主动刷新、重进房或重启浏览器。
- 执行轮次表只显示最近 N 条；累计轮次、总缺口、最慢点击等统计单独保存。
- 任何安全阀门不能为了省资源而删除，包括同房、同局、可下注、余额、限红、坐标和下注前检查。

## 功能需求

### R1. 4 元筹码支持

系统必须支持 4 元筹码，并且每个账号的单轮下注步数仍控制在 5 步以内。计划拆分不得生成平台没有对应筹码的金额。

验收：
- 金额 4、8、14、24、44 等可由合法筹码组合生成。
- 单账号 `chips` 长度不超过 5。
- 缺口不能因为 4 元筹码被过滤而产生。

### R2. 批量填写登录信息

a1/a2/a3/a4 的登录页填写按钮都必须可用。点击后应使用当前 UI 保存的平台网址、账号、密码、代理，不得继续使用旧缓存账号。

验收：
- 修改 UI 配置并保存后，重新打开登录页使用新值。
- a1/a2/a3/a4 都能独立填写。
- 代理格式 `IP|端口|代理账号|代理密码|到期时间` 能自动拆分供后端使用。

### R3. 进房状态反馈

账号已经进入房间并读到房间号/局号时，底部状态不得继续显示 `visual_loading` 或“加载中”。应显示“进房完成 / 房间已打开 / 已在目标房间”等明确状态。

验收：
- UI 卡片展示目标房间、当前房间、进房进度。
- 已读到完整局号时，不再显示加载态。

### R4. 有头主号可执行

系统不能要求所有账号都是无头。a2 作为有头主号时，也必须能参与计划生成和真实下注。

验收：
- a2 有头，其他账号无头时，计划仍能生成。
- 主号和副号都可执行真实下注。

### R5. 倒计时展示简化

UI 不再追求后端高频同步真实倒计时。后端捕捉到新一局可下注信号后，前端启动本地 12 秒倒计时；倒计时结束后自动转为不可下注。

验收：
- 可下注时文字为绿色。
- 不可下注时文字恢复蓝色。
- UI 倒计时只作操作参考，真实执行仍以轻量核心下注前检查为准。

### R6. 缺口原因展示

当出现缺口时，UI 必须能显示该账号计划金额、实际金额、缺口、筹码组合、执行耗时和失败原因。

验收：
- 最近执行轮次明细可看到每个账号的实际下注金额。
- 运行摘要显示总缺口、最慢整轮、最慢点击。

### R7. 计划生成时机

计划应尽量在开牌/派奖阶段提前准备，但真实发号只能在同房、同局、可下注、下注前检查通过后发生。

验收：
- UI 显示计划轮次。
- 计划事件应在真实点击执行前输出；同轮 `plan` 事件时间必须早于 `round_result` 事件时间。
- 若后续要实现派奖阶段预生成，必须先单独说明会触碰哪些状态读取链路风险。
- 若任一关键门槛失败，不发真实下注指令。

### R8. 副号金额随机性

副号金额不能长期呈现过于规律的固定模式。计划生成可参考旧 UI 的金额扰动思路，但不得引入旧 UI 的重采集链路。

验收：
- 最近 20 个完整计划内，副号金额不能全部相同；同一副号至少出现 2 种合法金额组合，除非余额不足或配置范围只允许一种金额。
- 主副合计仍符合对冲规则。

### R9. 余额不足自动剔除

某账号余额不足时，系统必须自动剔除该账号，并用剩余账号重新按 1 主 2 副生成计划。若原主号余额不足，优先由剩余账号中金额最多者继承为主号；后续可扩展为人工指定继承账号。低于 3 个可用账号时停止发号。

验收：
- 4 号变 3 号后仍能生成 1 主 2 副计划。
- 低于 3 个可用账号时不继续下注，并显示停止原因。

### R10. 低余额剔除线可配置

高级设置中提供“低余额剔除线”。操作者可自行设置低于多少余额视为不可用。

验收：
- 配置保存后重启 UI 仍生效。
- 计划生成使用当前配置值。

### R11. 可下注颜色

账号卡片处于可下注时，核心状态字体为绿色；不可下注时为蓝色。

验收：
- 状态切换不改变后端采集频率。
- 颜色只反映 UI 展示，不作为下注唯一判断。

### R12. 计划轮次与主副区分

本轮计划显示计划轮次。主号用土黄色与副号区分，副号保持普通样式。

验收：
- 每次新计划生成，计划轮次递增。
- 主号金额块明显区别于副号。

### R13. 运行时间

运行摘要区域显示本次轻量控制启动后的运行时间。UI 启动时刻只用于单账号初始余额，不参与该计时重置规则。

验收：
- 计时只做前端本地标签刷新，不触发额外后端状态采集。
- 暂停/停止时不影响 UI 启动时的单账号初始金额。

### R14. 单账号盈亏统计和充值提现记录

单账号盈亏区域显示 a1/a2/a3/a4 的初始余额、当前余额、当前盈亏。初始余额以 UI 启动后第一次读到的金额为准，不因中途暂停、停止、重新启动轻量控制而重置。

新增充值/提现记录功能只用于统计修正，不执行真实充值或提现。公式为：

`当前盈亏 = 当前余额 - 初始余额 - 累计充值 + 累计提现`

说明：充值不应被算成盈利，提现不应被算成亏损。

验收：
- 充值 100 后，在当前余额同步增加 100 的情况下，盈亏不被错误增加。
- 提现 100 后，在当前余额同步减少 100 的情况下，盈亏不被错误减少。
- 盈利为正数用蓝色，亏损为负数用红色。
- 每个账号可以查看或至少看到累计充值、累计提现。

### R15. 下注流水累计

原“发号门槛”区域改为 a1/a2/a3/a4 的下注流水累计。累计值来自下方执行轮次的实际下注金额，不用计划金额代替。原“待确认”按钮改为“重置流水”。

验收：
- 每轮完成后累计实际下注金额。
- 重置流水只清流水，不清执行轮次、不清盈亏初始余额。

### R16. 单账号快捷操作

账号卡片提供单账号重启、接管、进房操作。若自动进房已稳定实现，可保留手动进房作为兜底。

验收：
- 单账号按钮只影响对应账号。
- 账号卡片或简短事件记录显示进度和结果，不新增主界面调试日志面板。

### R17. 进房并行和进度

批量进房应并行执行，避免先进入的账号长时间等待导致被踢。UI 必须显示每个账号的进房目标、阶段、耗时和失败原因。

验收：
- 批量进房不再串行等待一个账号完成后才开始下一个。
- 可以选择 1/2/3 房。

### R18. 78 轮后中断诊断

系统必须能说明持续下注为什么在某轮后停止，例如余额不足、可用账号不足、状态等待超时、房间掉线、任务异常、人工暂停或急停。不得静默停止后只能靠人工重新点击启动。

验收：
- 每次等待下注窗口超时必须记录最小诊断摘要：当前轮次、等待耗时、参与账号房间/局号/余额/可下注摘要、进房阶段。
- 连续可恢复超时不得静默停止；应继续等待，或沿用现有低频自动回房机制，并在 UI 显示“等待下一局/重新进房中”。
- 不可恢复场景必须输出固定原因码，并停止真实发号。
- 运行摘要必须显示最近一次停止/等待原因。

### R19. 手动资源诊断与容量估算

需要提供人工触发或验收期使用的资源诊断报告，估算本机可同时运行多少套轻量 UI。该能力不得作为常驻运行面板，不得新增持续后台采样。

验收：
- 输出当前 Python/UI、Chrome/Chromium 进程数、内存占用、CPU 采样，采样窗口不少于 15 秒。
- 给出三项估算：按内存可运行套数、按 CPU 可运行套数、按浏览器实例数量可运行套数。
- 最终建议套数取三项最小值，再乘以 0.7 安全系数后向下取整。
- 资源诊断必须人工触发或仅在验收时运行，不进入主界面常驻刷新。

## 非目标

- 不实现真实充值、提现、转账。
- 不重写旧 UI。
- 不为了 UI 展示恢复高频 canvas 文本采集或旧 worker 重事件流。
- 不新增常驻资源监测仪表盘、主界面调试日志面板或无限增长执行明细表。
- 不为局号停更默认增加主动高频刷新、频繁重进房或自动重启浏览器。
- 不改变已经验证过的真实点击执行器，除非有单独明确指令。
