### 2. 结算时余额更新 ⏳

**代码位置**: `backend/app/engine/settlement.py::SettlementProcessor._update_account_balance()`

**验证结果**: ⏳ 逻辑正确，但需要等待开奖

**关键逻辑**:
```python
# 结算后更新余额
delta = amount + pnl  # 返还金额
new_balance = old_balance + delta

# 赢: delta = amount + (amount*odds//10000 - amount) = amount*odds//10000
# 输: delta = amount + (-amount) = 0
# 退款: delta = amount + 0 = amount
```

**验证方式**:
- 等待开奖完成
- 查询订单结算结果（is_win, pnl）
- 验证余额变化 = 初始余额 + 盈亏

**测试状态**: 投注成功，等待开奖中

## 余额流转完整流程

### 场景1: 投注并赢（赔率1.98）

```
1. 投注前余额: 20000.0
2. 投注金额: 10.0
3. 投注后余额: 20000.0 - 10.0 = 19990.0 ✅
4. 开奖结果: 赢
5. 盈亏计算: pnl = 10.0 * 1.98 - 10.0 = 9.8
6. 余额返还: delta = 10.0 + 9.8 = 19.8
7. 最终余额: 19990.0 + 19.8 = 20009.8 ⏳
```

### 场景2: 投注并输

```
1. 投注前余额: 20000.0
2. 投注金额: 10.0
3. 投注后余额: 20000.0 - 10.0 = 19990.0 ✅
4. 开奖结果: 输
5. 盈亏计算: pnl = -10.0
6. 余额返还: delta = 10.0 + (-10.0) = 0
7. 最终余额: 19990.0 + 0 = 19990.0 ⏳
```

### 场景3: 模拟模式投注

```
1. 投注前余额: 20000.0
2. 投注金额: 10.0 (模拟)
3. 投注后余额: 20000.0 (不扣减) ✅
4. 开奖结果: 赢/输
5. 余额不变: 20000.0 ✅
```

## 关键发现

### 1. 模拟模式 vs 真实模式

| 模式 | simulation | 余额扣减 | 结算返还 | 用途 |
|------|-----------|---------|---------|------|
| 模拟模式 | 1 | ❌ 不扣减 | ❌ 不返还 | 测试策略 |
| 真实模式 | 0 | ✅ 扣减 | ✅ 返还 | 真实投注 |

**重要**: 原有E2E测试全部使用模拟模式，无法验证真实余额扣减！

### 2. 余额扣减时机

```
订单状态流转:
pending → betting → bet_success → settled
                        ↑              ↑
                    余额扣减        余额返还
```

**投注时扣减**:
- 时机: 订单状态变为 `bet_success` 后
- 金额: 订单金额（amount）
- 代码: `executor.py::_deduct_balance()`

**结算时返还**:
- 时机: 订单状态变为 `settled` 后
- 金额: 本金 + 盈亏（amount + pnl）
- 代码: `settlement.py::_update_account_balance()`

### 3. 平台限制

**重复投注检测**:
- 平台会检测相同期号、玩法、金额的重复投注
- 返回错误: `succeed=6, message=注单有重复,请检查!`
- 影响: 连续运行相同测试可能失败

**解决方案**:
- 每次测试使用不同的投注金额
- 或者等待下一期再测试
- 或者使用不同的玩法代码
