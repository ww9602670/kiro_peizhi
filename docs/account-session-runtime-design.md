# 第三方账号统一会话与多策略执行工程设计

日期：2026-05-02

## 设计原则

1. 一个第三方物理账号只有一个运行态会话所有者。
2. 登录、重登、验证码、余额、赔率、下注、结算必须可串行、可限流、可追踪。
3. 策略信号计算可以并行，平台请求必须按账号串行。
4. 多账号可以并行，但同平台共享组必须节流。
5. 本次整改优先使用现有数据库结构，不做 schema migration。
6. 遇到无法兼容的现有逻辑时停止并上报，不做隐式扩展。

## 模块设计

### 1. 统一会话运行时

建议模块：`backend/app/engine/session_runtime.py`

修改目标：

1. 新增账号运行态会话入口，按物理账号维度管理平台 adapter、登录状态、请求锁、登录锁、恢复锁。
2. 提供 `ensure_logged_in(reason)`、`run_platform_call(reason, func)`、`recover(reason)` 等统一入口。
3. 同一个账号同一时间只允许一个登录或重登动作。
4. 同一个账号的平台 API 调用默认串行。
5. 记录最近登录时间、最近失败原因、是否处于平台风控熔断状态。

修改约束：

1. 不新增外部依赖。
2. 不新增数据库表。
3. 不改变 adapter 的平台协议字段含义。
4. 不吞掉异常，必须保留可追踪原因。

禁止事项：

1. 禁止每个调用点自行创建新登录链路。
2. 禁止无限重试。
3. 禁止把 403、Cloudflare、验证码异常当普通网络失败继续高频重试。

### 2. EngineManager

模块：`backend/app/engine/manager.py`

修改目标：

1. 持有统一会话运行时 registry。
2. `start_worker` 获取同一账号运行态，不再让 worker 独立拥有不可共享的登录链路。
3. 提供查询运行中 worker 或运行态的方法，供账号验证、赔率刷新复用。
4. 多策略仍按 `account_id + platform_type` 热更新进入现有 worker。

修改约束：

1. 保持当前 worker registry 行为兼容。
2. 不改变策略启动 API 返回结构。
3. 不修改共享账号 detector 禁止下注逻辑。

禁止事项：

1. 禁止启动同账号同盘口的第二个真实 worker。
2. 禁止绕过 worker lock。

### 3. SessionManager

模块：`backend/app/engine/session.py`

修改目标：

1. 将登录、重登、心跳恢复纳入统一会话控制。
2. 登录失败后执行冷却，避免连续验证码请求。
3. 发现平台风控类错误时进入熔断状态。
4. 保持 10 秒心跳，但心跳失败后的恢复必须受统一恢复锁控制。

修改约束：

1. 不删除现有心跳能力。
2. 不把心跳失败直接升级为高频重登。
3. 不改变已有告警服务接口。

禁止事项：

1. 禁止心跳、结算、拉期号同时触发多次重登。
2. 禁止恢复失败后继续循环登录。

### 4. AccountWorker

模块：`backend/app/engine/worker.py`

修改目标：

1. worker 启动时通过统一会话 `ensure_logged_in`，不得无条件创建独立登录链路。
2. 当前按下注时机分组的执行计划继续保留。
3. 同一个账号的平台请求通过统一运行态串行执行。
4. `_revalidate_group_window`、`_fetch_install_with_retry`、结算恢复不得绕过统一恢复链路。
5. 当前期执行计划必须稳定，新策略热更新默认从下一期生效，除非仍处于合法窗口且明确允许加入。

修改约束：

1. 不修改策略算法。
2. 不修改开奖数据结构。
3. 不删除已有 worker lock。
4. 不改变订单状态机语义。

禁止事项：

1. 禁止因一个策略失败停止同 worker 全部策略，除非会话已熔断或 worker lock 丢失。
2. 禁止在预提交校验失败后每 5 秒无限重试到封盘。

### 5. BetExecutor

模块：`backend/app/engine/executor.py`

修改目标：

1. 真实下注提交必须通过账号级平台请求锁。
2. 同一时间同账号不得并发调用 `Confirmbet`。
3. 赔率变更重试只允许在合法窗口内执行一次。
4. 下注失败原因必须区分超时、封盘、会话异常、赔率变更、平台拒绝。

修改约束：

1. 不改变订单幂等键生成方式。
2. 不改变真实下注成功后的本地扣款规则。
3. 不改变模拟下注逻辑。

禁止事项：

1. 禁止赔率变更导致无关玩法告警。
2. 禁止超过安全窗口继续重试提交。

### 6. Settlement

模块：`backend/app/engine/settlement.py`

修改目标：

1. 结算链路使用统一会话执行平台查询。
2. 余额接口异常时先检查会话，再受控恢复。
3. 恢复失败时保留待结算或待重试状态，不得直接把余额写为 0。
4. 平台结算数据拉取失败要保留可重试状态和告警原因。

修改约束：

1. 不删除历史投注记录。
2. 不改变已结算订单的盈亏计算规则。
3. 不做破坏性补结算。

禁止事项：

1. 禁止接口异常被当作真实余额。
2. 禁止单次结算失败触发高频重登。

### 7. Accounts API

模块：`backend/app/api/accounts.py`

修改目标：

1. 绑定账号仍只保存资料，不登录平台。
2. 重新验证账号必须通过统一会话。
3. worker 正在运行时，验证账号复用运行会话，不得另起登录。
4. 验证成功写入余额、盘口能力、赔率同步结果。
5. 验证失败保留明确原因。

修改约束：

1. 不改变绑定账号接口含义。
2. 不改变账号权限校验。
3. 不把 worker 正在运行的账号误标为离线。

禁止事项：

1. 禁止验证账号顶掉真实下注 worker。
2. 禁止验证失败清空已有可信余额。

### 8. Odds API

模块：`backend/app/api/odds.py`

修改目标：

1. 手动刷新赔率通过统一会话执行。
2. worker 正在运行时复用运行会话。
3. 平台关闭或赔率不可取时返回明确中文提示。
4. 非当前策略版本涉及的赔率变化不得产生无关告警。

修改约束：

1. 不改变赔率确认表结构。
2. 不改变前端已使用的响应字段。

禁止事项：

1. 禁止刷新赔率另起登录顶掉 worker。
2. 禁止无关盘口赔率变动影响 2.0 策略下注。

### 9. Strategy API 与下注时机

模块：

1. `backend/app/api/strategies.py`
2. `backend/app/utils/strategy_timing.py`

修改目标：

1. 创建、编辑、启动策略都必须检测下注时机。
2. 默认下注时机 88 秒。
3. 允许范围 10-100 秒。
4. 同账号、同盘口、同方向真实下注策略默认间隔 20 秒。
5. 自动分配优先使用靠近请求值的合法时机。
6. 无合法时机时阻止保存或启动，并返回明确原因和建议。

修改约束：

1. 不改变策略授权逻辑。
2. 不改变策略类型注册。
3. 模拟策略是否占用真实下注时机必须保持一致规则并有测试覆盖。

禁止事项：

1. 禁止为了避开冲突静默修改投注方向或策略玩法。
2. 禁止创建无法解释下注时机的运行策略。

### 10. Shared Market Runtime

模块：`backend/app/engine/shared_market_runtime.py`

修改目标：

1. 本次默认不修改采集频率。
2. 共享账号继续只负责开奖数据。
3. 如果共享数据异常，真实下注 worker 不得集体高频 fallback 到平台自采集。

修改约束：

1. 不使用真实下注账号作为共享采集账号。
2. 不改变管理员共享池管理逻辑。

禁止事项：

1. 禁止共享账号和真实下注账号共用会话。
2. 禁止共享异常放大成所有真实账号高频请求平台。

## 错误处理

必须区分以下状态：

1. `session_online`：会话正常。
2. `session_reconnecting`：受控恢复中。
3. `session_blocked`：平台风控或验证码异常，停止自动重试。
4. `balance_sync_failed`：余额同步失败，保留上次可信余额。
5. `odds_sync_failed`：赔率同步失败，不影响无关盘口策略。
6. `bet_timing_conflict`：下注时机无法自动分配。
7. `platform_rate_limited`：平台级限流中。

## 测试策略

必须覆盖：

1. 绑定账号不登录平台。
2. 验证账号正常只走统一会话。
3. worker 运行时验证账号不另起登录。
4. worker 运行时刷新赔率不另起登录。
5. 同账号多策略只启动一个 worker。
6. 同账号多策略下注时机自动分隔。
7. 编辑和启动策略重新检测下注时机。
8. 同账号真实下注串行提交。
9. 余额接口异常不写 0。
10. 403 或验证码异常进入熔断，不继续重试。
11. 多账号可并行运行，但同平台登录受限流。

## 执行中止条件

出现以下任一情况，执行 agent 必须停止并上报：

1. 需要新增数据库表或破坏性迁移。
2. 需要修改策略算法。
3. 需要删除历史订单或结算记录。
4. 需要修改 nginx、域名、SSL、systemd 配置。
5. 无法在测试中证明 worker 运行时验证不会另起登录。
6. 无法在测试中证明余额异常不会写 0。
7. 发现当前未提交改动和本次整改冲突。
