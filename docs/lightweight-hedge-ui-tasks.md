# 轻量对冲 UI 任务文档

日期：2026-06-24

## 执行原则

1. 严格按阶段 1-6 顺序实现。
2. 每个阶段完成后跑对应测试，并人工确认 UI。
3. 不把旧 UI 的重资源逻辑搬入新 UI。
4. 旧 UI 继续保留，新 UI 独立实现。
5. 阶段 4 和阶段 5 触碰保护链路，必须二次审核后再实施。

## 阶段 0：文档审核

负责人：gpt-5.5 审核 agent

输入：
- `docs/lightweight-hedge-ui-requirements.md`
- `docs/lightweight-hedge-ui-design.md`
- `docs/lightweight-hedge-ui-tasks.md`
- `docs/ui-drafts/lightweight-hedge-console-v3.html`

审核要求：
1. 判断文档是否足以指导无上下文开发 agent。
2. 判断是否有把旧 UI 高频刷新逻辑搬入新 UI 的风险。
3. 判断阶段 4/5 的保护门禁是否明确。
4. 输出：通过 / 不通过。
5. 不通过时列出必须修改的文档点。

验收：
- 审核 agent 明确给出“通过”后，才能进入阶段 1。

## 阶段 1：新 UI 空壳可运行

目标：
实现独立轻量 UI 入口，不接真实后端。

建议修改范围：
- 新增 `bet_desktop/ui/lightweight_dashboard.py`
- 新增 `bet_desktop/ui/lightweight_models.py`
- 新增 `bet_desktop/ui/run_lightweight_dashboard.py`
- 新增或更新轻量 UI 测试文件

任务：
1. 实现平台配置、运行控制、执行记录三个页面。
2. 复刻 V3 草图的核心布局。
3. 实现主号切换 UI。
4. 实现高级设置默认折叠。
5. 实现假数据驱动的账号状态、本轮计划、执行记录、日志。

禁止：
- 不导入 `cluster_process_worker`。
- 不启动浏览器。
- 不读取/写入真实配置文件。
- 不改旧 `main_dashboard.py`。

验收：
- 新 UI 可以单独启动。
- 主号切换会刷新本轮计划。
- 高级设置默认折叠。
- 运行页普通用户界面不显示调试按钮。

测试建议：
- UI 构造测试。
- 主号切换模型测试。
- 高级设置默认状态测试。

## 阶段 2：平台配置读取保存

目标：
让新 UI 能读取和保存旧配置结构，并新增代理到期字段。

建议修改范围：
- `bet_desktop/ui/lightweight_config_store.py`
- `bet_desktop/ui/lightweight_models.py`
- 轻量配置测试

任务：
1. 读取 `platform_proxy_profiles.json`。
2. 支持 `platform_slots`。
3. 支持字段：平台名称、登录地址、目标地址、目标房间、代理地址、代理端口、代理账号、代理密码、代理到期、平台账号、平台密码。
4. 保存配置时保留未知字段。
5. 平台摘要只显示名称、代理到期、平台账号。
6. 实现代理一键自动填写按钮的 UI 入口；实际自动填写逻辑可先留 adapter stub。

禁止：
- 不改变旧配置读取行为。
- 不删除旧配置字段。
- 不保存明文日志。

验收：
- 读取旧配置不崩溃。
- 保存后旧 UI 仍可读取配置。
- 代理到期可显示。

测试建议：
- 临时配置文件 round-trip 测试。
- 未知字段保留测试。
- 缺失字段容错测试。

## 阶段 3：启动与登录功能接入

目标：
复用旧 UI 已验证的平台启动和填写登录能力，但只接入轻量摘要。

建议修改范围：
- `bet_desktop/ui/lightweight_controller.py`
- `bet_desktop/ui/lightweight_dashboard.py`
- 可能新增 `bet_desktop/ui/lightweight_browser_adapter.py`

任务：
1. 实现单账号启动命令。
2. 实现批量启动命令。
3. 实现单账号填写登录命令。
4. 实现批量填写登录命令。
5. UI 显示启动/登录摘要。
6. 防止按钮重复提交。

允许复用：
- 旧 UI 的配置构造逻辑。
- 旧 UI 的 worker 命令语义。

边界：
- 只允许包装已有启动/登录命令或新增 fake adapter。
- 不允许修改旧 `MainDashboard` 展示逻辑。
- 不允许把旧 UI widget 作为 adapter 依赖。

禁止：
- 不搬旧 UI 的事件刷屏。
- 不显示原始 worker 高频日志。
- 不在 UI 线程启动 Playwright。

验收：
- 启动按钮能发出正确命令。
- 填登录按钮能发出正确命令。
- 摘要日志不刷屏。

测试建议：
- 使用 fake adapter 验证命令。
- 验证批量按钮只发送目标账号。

## 阶段 4：接管大厅与进房接入

状态：受保护阶段，实施前必须二次审核。

二次审核必须覆盖：
- 余额。
- 局号。
- 状态机。
- 倒计时。
- 房间。
- 限红。
- 坐标。
- 真实下注链路。

目标：
复用当前已验证的接管和进房能力。

建议修改范围：
- `bet_desktop/ui/lightweight_controller.py`
- `bet_desktop/ui/lightweight_browser_adapter.py`
- 必要时只做旧 worker 命令包装

任务：
1. 按当前主号计算副号列表。
2. 批量接管只发送副号。
3. 批量进房支持 4 账号。
4. 批量释放支持 4 账号。
5. 接管/进房结果显示摘要。
6. 详细失败原因写诊断日志。

禁止：
- 不改 `_handoff_to_headless` 内部逻辑。
- 不改 `_enter_headless_room` 内部逻辑。
- 不改浏览器窗口尺寸、profile、坐标识别链路。
- 不增加新的持续探针。

验收：
- 主号切换后接管对象正确变化。
- 副号可以接管为无头。
- 4 账号可以进入目标房间。
- 接管失败不导致 UI 卡死。

测试建议：
- fake adapter 测试主号切换后的接管列表。
- 命令生成测试。
- 人工实盘前先用大厅状态测试。

## 阶段 5：轻量核心执行接入

状态：受保护阶段，实施前必须二次审核。

二次审核必须覆盖：
- 余额。
- 局号。
- 状态机。
- 倒计时。
- 房间。
- 限红。
- 坐标。
- 真实下注链路。

目标：
接入独立测试脚本验证过的轻量执行思路，支持 4 账号对冲。

建议修改范围：
- 新增 `bet_desktop/ui/lightweight_execution_core.py`
- `bet_desktop/ui/lightweight_controller.py`
- 可从 `scripts/live_interval_acceptance_probe.py` 抽取纯函数到可测试模块

任务：
1. 抽取或复用可配置账号列表、主号、副号、无头账号逻辑。
2. 抽取或复用 4 账号金额拆分和筹码拆分逻辑。
3. 实现统一发号者。
4. 发号前并行读取 4 账号摘要状态。
5. 校验同房、同局、可下注、倒计时门槛。
6. 发送计划给各 worker 并行执行。
7. 聚合 worker 最终结果。
8. UI 显示完整、缺口、跳过、失败。

禁止：
- 不复制旧 UI 的执行循环。
- 不让 UI 逐账号串行等待导致错过下注窗口。
- 不把执行前页面快照旧局号检查重新加回去。
- 不逐筹码刷新 UI。
- 不绕过 worker 最终结果。

验收：
- 4 账号计划正确。
- 主号切换后计划正确。
- 倒计时不足时不发号。
- 任一账号不同房/不同局时不发号。
- 执行结果按最终 worker 返回聚合。

测试建议：
- 计划拆分单元测试。
- 主号切换计划测试。
- 发号门槛测试。
- 结果聚合测试。
- fake worker 并行执行测试。

## 阶段 6：日志、异常、资源摘要与交付

目标：
完善人类可用性，并交付人工测试。

边界：
- 如果阶段 6 提前开发，只能接入轻量 UI 自身日志。
- 不接入旧 UI 高频诊断源。
- 不把 worker 原始刷屏日志直接显示到主界面。

建议修改范围：
- `bet_desktop/ui/lightweight_dashboard.py`
- `bet_desktop/ui/lightweight_controller.py`
- 测试文件

任务：
1. 主日志只显示摘要。
2. 日志行数限制。
3. 重复状态合并。
4. 异常 banner。
5. 执行记录导出或结构化保存。
6. 资源摘要只显示最近值。
7. 启动前/退出时做轻量残留提示，不默认强杀未知进程。

禁止：
- 不把诊断文件内容实时刷到 UI。
- 不高频写资源日志。
- 不隐藏真实执行异常。

验收：
- 连续运行日志不造成明显卡顿。
- 缺口和异常清晰显示。
- UI 能给人类测试。

测试建议：
- 日志上限测试。
- 摘要合并测试。
- 异常显示测试。
- UI 启动烟测。

## 开发 agent 交接要求

开发 agent 使用 `gpt-5.3-codex-spark`。

开发 agent 必须遵守：
1. 先实现阶段 1，不得跳到接管或真实执行。
2. 每阶段结束后报告：
   - 修改文件
   - 完成内容
   - 测试结果
   - 是否触碰保护链路
3. 不得还原用户或其他 agent 的改动。
4. 不得直接大改旧 UI。
5. 阶段 4/5 需要等待主线程明确放行。

## 人类测试交付清单

交付时必须提供：
1. 新 UI 启动命令。
2. 配置文件路径。
3. 默认主号切换说明。
4. 高级设置说明。
5. 已跑测试列表。
6. 已知风险。
7. 真实平台测试步骤。

## 第一批开发范围建议

为了遵守保护规则，第一批只开发：
- 阶段 1：新 UI 空壳。
- 阶段 2：平台配置读取保存。
- 阶段 3：启动与登录命令 adapter，可用 fake adapter 先验收。

阶段 4/5 待单独审核后继续。
