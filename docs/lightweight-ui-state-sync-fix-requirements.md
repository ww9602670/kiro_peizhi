# 轻量 UI 局号与可下注状态同步修复需求

## 背景

轻量 UI 已经接入登录、接管、进房和轻量核心状态轮询，但现场观察发现：

1. 真实游戏画面已经进入新局并显示“下注中”，UI 仍显示旧局号。
2. 真实游戏画面处于可下注窗口，UI 仍显示“数据过期”或“不可下注”。
3. 底层日志已经出现新局号与下注动作信号，但轻量 UI 没有正确消费这些信号。
4. 这次修复不能把旧 UI 的高频刷新、大量诊断面板或重状态源搬进轻量 UI。

## 现场证据

最小证据摘录：

- 真实画面：房间 `T001`，牌局编号更新为 `50-1782374106-8541662349-1442`，画面显示“下注中”。
- 轻量底层事件：a2 近期状态里已出现更新后的 `canvas_game_no=50-1782374184-8541665428-1460`。
- 同一状态里同时出现 `runtime_action=3` 或 `runtime_action=5`，但也出现 `game_ready=False`、`hall_ready=True`，导致 UI 被误导成大厅或过期。
- UI 当时仍显示旧局号 `50-1782373905-8541654406-11295`。

结论：问题不是浏览器完全没有采到数据，而是“轻量状态输出层”和“UI 状态消费层”没有把可信字段整理成稳定的轻量状态。

## 目标

1. UI 能及时显示当前房间的可信局号。
2. UI 能稳定在“可下注”和“不可下注”之间切换。
3. 后端一旦确认可下注，UI 启动 12 秒本地参考倒计时。
4. 同一局后续刷新不能重置 UI 本地倒计时。
5. UI 倒计时归零后自动显示“不可下注”。
6. 余额继续展示，但不要求为余额增加高频刷新。
7. 真实下注前检测、发号、点击、坐标、筹码拆分和保护逻辑保持不变。

## 非目标

1. 不重写下注执行逻辑。
2. 不修改真实下注前 preflight。
3. 不修改坐标识别、筹码坐标、下注区域坐标和点击执行函数。
4. 不开启旧 UI 那套重型高频状态面板。
5. 不为了 UI 显示倒计时而每秒读取浏览器。
6. 不把前端参考倒计时作为真实下注依据。

## 需求

### R1. 轻量状态输出必须有统一的显示态

状态输出层应向 UI 提供统一字段：

- `display_game_no`: UI 展示用局号。
- `display_room_label`: UI 展示用房间。
- `display_balance_cents`: UI 展示用余额。
- `display_betting_open`: UI 展示用可下注状态。
- `display_phase`: UI 展示用阶段，值只需要 `betting_open`、`betting_closed`、`hall`、`unknown`。
- `display_source`: 说明这次显示态来自哪个可信来源，便于调试。

### R2. 局号来源必须按可信优先级选择

局号选择优先级：

1. 当前画面可信 `canvas_game_no`。
2. 当前快照 `snapshot_game_no`。
3. 当前 guard 局号 `guard_game_no`。
4. 前端对象扫描中的当前房间局号，但必须和当前锁定房间一致。
5. 不允许用明显旧的 `label_internal_game_no` 覆盖当前可信局号。

### R3. 可下注状态必须识别运行时动作

可下注判断优先级：

1. `runtime_action=3` 或 `frontend_runtime_action=3`，视为可下注。
2. `snapshot.betting_open=True` 或 `guard.betting_open=True`，视为可下注。
3. `runtime_action` 为结算、派彩、等待类动作时，视为不可下注。
4. 不允许因为 `game_ready=False`、`hall_ready=True` 单独覆盖“当前已在房间、有局号、有坐标、有房间号”的证据。

### R4. 房间内判断必须使用组合证据

只要同时满足以下任意组合，UI 应认为账号在房间内：

- 有锁定房间号或房间标签，并且有当前局号。
- 有下注区域坐标或筹码坐标，并且有房间标签。
- 有当前房间局号和余额。

在这些情况下，`hall_ready=True` 不能单独把 UI 状态改成大厅。

### R5. UI 本地倒计时只用于展示

1. 收到 `display_betting_open=True` 且局号发生变化时，UI 本地倒计时从 12 秒开始。
2. 同一局重复收到可下注状态时，不重置倒计时。
3. 收到 `display_betting_open=False` 时，UI 立即显示不可下注。
4. 倒计时归零时，UI 自动显示不可下注。
5. 真实下注发号仍必须使用后端下注前检测，不得使用 UI 倒计时决策。

## 验收标准

1. 单元测试覆盖：局号优先级、`runtime_action=3` 可下注、`runtime_action=5` 不可下注、房间内证据不被大厅误判覆盖。
2. 单元测试覆盖：同一局刷新不重置 UI 12 秒倒计时。
3. 单元测试覆盖：UI 倒计时归零后显示不可下注。
4. `python -m py_compile` 覆盖修改过的 Python 文件。
5. `python -m pytest bet_desktop\tests\test_lightweight_hedge.py -q` 通过。
6. 人工现场验证：真实画面新局出现后，UI 局号应跟随更新；真实画面下注中时，UI 应显示“可下注 xx秒”；倒计时结束后 UI 应显示“不可下注”。
