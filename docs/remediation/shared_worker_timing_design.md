# 共享数据、worker 时机与结算链路第一阶段技术设计

生成时间：2026-05-03

依据：

- `docs/shared-market-worker-timing-remediation-report.md`
- `docs/remediation/phase1_current_chain_report.md`

执行约束：本文件仅为技术设计，不修改业务代码。

## 设计目标

第一阶段目标是把开奖数据、下注时机、worker 自恢复、结算和前端展示统一到一条清晰链路：

1. 共享账号正常时，由共享采集器统一提供期号、开奖、封盘倒计时、开奖倒计时。
2. worker 和前端正常情况下只消费本系统共享快照，不直接请求第三方平台开奖倒计时。
3. 开奖倒计时归零后，由共享采集器执行专项刷新，避免盲目 25 秒轮询造成开奖数据滞后。
4. worker 下注前不再调用第三方平台倒计时接口，只校验本地快照新鲜度和期号窗口。
5. 共享异常时才允许 worker 低频本地回退，且回退结果不得写回共享池。
6. 结算链路独立于下注主循环，结算延迟不阻塞下一期下注。
7. 策略生命周期不再被 `verification_stale` 硬阻断，实际运行交给 worker 登录和自恢复链路。

## 1. 共享快照字段契约

共享快照必须成为前端、worker、管理员页面共同消费的唯一事实来源。

建议字段：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `shared_group_id` | integer | 共享组 ID。 |
| `snapshot_version` | integer | 快照递增版本，防止旧数据覆盖新数据。 |
| `market_data_state` | string | 共享数据源总体状态。 |
| `draw_state` | string | 开奖节点状态。 |
| `current_issue` | string | 当前可下注期号。 |
| `current_state` | integer | 当前盘口状态，1=可下注，2=封盘，3=开奖中，0=未知。 |
| `close_countdown_sec` | integer | 封盘倒计时。 |
| `open_countdown_sec` | integer | 开奖倒计时。 |
| `pre_issue` | string | 上期开奖期号。 |
| `pre_result` | string | 上期开奖结果。 |
| `fetched_at` | datetime | 共享账号实际采集成功时间。 |
| `deadline_close_at` | datetime | 根据 `fetched_at + close_countdown_sec` 计算的封盘截止时间。 |
| `deadline_draw_at` | datetime | 根据 `fetched_at + open_countdown_sec` 计算的开奖预计时间。 |
| `next_normal_refresh_at` | datetime | 下一次普通 25 秒采集时间。 |
| `next_draw_retry_at` | datetime | 下一次开奖专项刷新时间。 |
| `last_error` | text | 最近一次共享采集异常摘要，只给后端日志和管理员使用。 |
| `message_code` | string | 前端展示用日志编号。 |
| `message_text` | string | 前端展示用简短中文提示。 |

写入规则：

1. 同一 `shared_group_id` 写入必须串行。
2. 新快照写入时必须比较 `snapshot_version` 或采集时间，旧数据不能覆盖新数据。
3. 只拿到部分数据时不得标记为正常状态。
4. worker 和操作者前端的本地回退数据不得写入共享池。

## 2. market_data_state / draw_state 状态定义

`market_data_state` 表示共享数据源是否可用。

| 状态 | 含义 | 前端动作 | worker 动作 |
| --- | --- | --- | --- |
| `shared_ok` | 共享数据正常。 | 正常展示期号、开奖、倒计时。 | 正常消费共享快照。 |
| `shared_error` | 共享账号登录、采集或接口异常。 | 弹窗提示 `数据更新变慢，可能影响投注，请联系管理员处理。日志编号：SHARED-002。` | 允许 80 秒低频本地回退。 |
| `shared_stale` | 共享快照超过可用新鲜度。 | 同 `SHARED-002`。 | 允许 80 秒低频本地回退。 |
| `market_closed` | 平台停盘。 | 显示 `当前处于停盘`。 | 停止新下注，继续结算已有订单。 |

`draw_state` 表示开奖节点进度。

| 状态 | 含义 | 前端动作 | worker 动作 |
| --- | --- | --- | --- |
| `normal` | 未处于开奖专项等待。 | 正常每秒倒计时。 | 正常读取快照。 |
| `draw_pending` | 开奖倒计时已归零，正在专项刷新。 | 显示等待开奖或正在获取开奖数据。 | 只读共享快照，不本地回退。 |
| `draw_wait_retry` | 第 6 次专项刷新仍未拿到新数据。 | 显示 `开奖数据暂未获取，10秒后再次刷新`。 | 按 `next_draw_retry_at` 再读共享快照，不 5 秒持续追问。 |

状态设计约束：

1. `draw_pending` 和 `draw_wait_retry` 不是失败状态。
2. `draw_pending` 和 `draw_wait_retry` 不触发 worker 本地回退。
3. `market_closed` 可以覆盖 `draw_state`，但不能阻断结算分支。
4. 状态变化才产生告警，持续状态不重复刷屏。

## 3. 开奖专项刷新状态机

普通阶段：

1. 共享采集器每 25 秒请求一次第三方平台。
2. 每次成功采集后写入共享快照。
3. 用 `fetched_at + open_countdown_sec` 计算开奖预计时间。

开奖归零阶段：

1. 到达开奖预计时间后，不立即认定新开奖数据可用。
2. 设置 `draw_state=draw_pending`。
3. 暂停与专项刷新重叠的普通 25 秒采集。
4. 按以下节奏刷新：
   - 第 1 次：开奖归零后 10 秒。
   - 第 2 次：再等 10 秒。
   - 第 3 次：再等 10 秒。
   - 第 4 次：再等 5 秒。
   - 第 5 次：再等 3 秒。
   - 第 6 次：再等 1 秒。
5. 任意一次拿到新期号或正确上期开奖结果，则写入共享快照，清除 `draw_pending`，回到 25 秒普通采集。
6. 第 6 次仍未拿到新数据，设置 `draw_state=draw_wait_retry`，前端提示 `开奖数据暂未获取，10秒后再次刷新`。
7. 之后每 10 秒继续刷新，直到拿到新数据或检测到停盘。
8. 检测到停盘时设置 `market_data_state=market_closed`，停止本期开奖专项刷新。

停盘恢复：

1. 停盘后共享采集器以低频方式检测是否恢复开盘。
2. 恢复开盘时，必须拿到有效期号、封盘倒计时和开奖倒计时，才能回到 `shared_ok`。
3. 停盘期间 worker 不生成新下注信号，但结算分支继续运行。

## 4. worker 读取共享快照规则

worker 正常获取期号、开奖、倒计时的来源顺序：

1. 优先读取共享快照。
2. 快照为 `shared_ok` 且未过期，直接使用。
3. 快照为 `draw_pending`，继续等待共享采集器专项刷新。
4. 快照为 `draw_wait_retry`，按 `next_draw_retry_at` 再读取。
5. 快照为 `market_closed`，停止本期新下注，继续结算。
6. 快照为 `shared_error` 或 `shared_stale`，才允许进入本地回退。

读取频率：

1. worker 读本地共享快照可以跟随自身循环，例如 5 秒一次。
2. 读本地共享快照不等于请求第三方平台。
3. `draw_wait_retry` 后不再 5 秒持续追问，应按后端给出的下一次刷新时间读取。

禁止行为：

1. 共享正常时，worker 不得调用操作者账号采集开奖倒计时。
2. `draw_pending` 或 `draw_wait_retry` 时，worker 不得触发本地回退。
3. worker 不得把本地采集结果写入共享池。

## 5. worker 本地回退规则

触发条件：

1. `market_data_state=shared_error`。
2. `market_data_state=shared_stale`。
3. 共享采集器不可用。
4. 共享快照缺失且无法由共享采集器恢复。

不触发条件：

1. `draw_state=draw_pending`。
2. `draw_state=draw_wait_retry`。
3. 共享账号正在开奖专项刷新。
4. 前端只是等待新开奖数据。

执行规则：

1. 本地回退频率最多 80 秒一次。
2. 节流粒度按第三方账号或 worker，不按策略。
3. 回退数据只服务当前 worker。
4. 回退数据不得写入 `shared_market_snapshots`。
5. 前端提示：`数据更新变慢，可能影响投注，请联系管理员处理。日志编号：SHARED-002。`
6. 管理员端记录详细异常，包括共享组、平台、账号、链接、失败接口、原始摘要。

## 6. 下注前快照新鲜度保护

目标：

取消下注前第三方平台倒计时强校验，但不能无条件使用旧快照。

下注前本地校验：

1. 当前快照状态必须是 `shared_ok`。
2. 当前期号必须与本轮执行计划期号一致。
3. 快照年龄不能超过允许新鲜度。
4. 根据 `deadline_close_at` 计算后，仍处于允许下注窗口。
5. 当前状态不能是停盘、共享异常、共享过期。
6. close countdown 必须大于系统安全阈值。

失败动作：

1. 快照过期：跳过本期下注，提示共享数据异常。
2. 期号变化：跳过旧期号，进入新期号计划。
3. 停盘：停止新下注，继续结算。
4. 下注接口返回失败后，才进入账号自检链路。

下注失败后的自检顺序：

1. 检测心跳。
2. 检测自身账号当前盘口状态。
3. 如会话异常，执行重登。
4. 如平台返回停盘，停止新下注。
5. 如多次封盘失败，产生异常日志并提醒管理员。

## 7. 结算独立分支设计

目标：

结算不能阻塞 worker 下一期下注。

触发时机：

1. 每期下注完成后，登记待结算期号。
2. 开奖倒计时归零后 20 秒首次拉取结算数据。
3. 后续退避：10 秒、5 秒、8 秒、之后每 10 秒。
4. 最长等待 10 分钟。

执行方式：

1. 按第三方账号维度建立结算分支或后台任务。
2. 同一账号的结算请求串行执行。
3. 多策略同账号不允许各自并发拉结算接口。
4. 多账号同时结算可增加 0 至 3 秒错峰。
5. 结算分支使用 worker 的 `session_runtime`，遇到会话异常先恢复再重拉。
6. 开奖数据获取和结算数据获取互不阻塞。
7. 收到停盘状态时，结算分支仍继续处理已有订单。

状态流转：

1. `bet_success` -> `settlement_pending`
2. `settlement_pending` -> `settled`
3. `settlement_pending` -> `settle_failed`

失败规则：

1. 10 分钟内没有有效结算数据，不提前标记 `settle_failed`。
2. 超过 10 分钟或明确不可恢复，才标记 `settle_failed`。
3. 标记失败后仍保留补偿入口。

## 8. 账号验证状态与策略生命周期解耦设计

目标：

账号绑定验证用于记录平台能力，不再主导策略生命周期。

创建策略：

1. 只要求账号存在、归属当前操作者、策略已授权。
2. 不因 `verification_stale=true` 阻止创建。
3. 如历史没有任何平台能力记录，可提示但不硬阻断。

编辑策略：

1. 仍要求策略处于可编辑状态。
2. 不因绑定账号验证过期阻止编辑。
3. 平台类型选择应来自账号配置或最近有效能力记录。

启动策略：

1. 不因 `verification_stale=true` 阻止启动。
2. 启动后由 worker session runtime 负责登录、心跳、重登。
3. 登录失败、盘口异常、余额异常时由 worker 产生明确中文告警。

重启恢复：

1. 服务重启后，状态为 running 的策略应尝试恢复 worker。
2. 不因 `verification_stale=true` 跳过恢复。
3. 如果账号被禁用、删除、kill switch、共享检测账号，则仍应跳过。

保留验证的用途：

1. 绑定账号时确认账号、密码、链接、赔率、盘口能力。
2. 给前端展示最近验证信息。
3. 给管理员排查账号状态。
4. 不作为运行期硬门禁。

## 9. 账号被顶自动重登设计

现有基础：

1. 每个第三方账号拥有独立 `session_runtime`。
2. session runtime 有登录锁、请求锁、恢复锁。
3. 心跳每 10 秒执行一次。
4. 连续 3 次心跳失败后自动重连。
5. 平台返回会话异常时，执行恢复后重试一次平台调用。

第一阶段要求：

1. 保留单账号单 runtime 的串行请求模型。
2. 被顶号、会话过期、登录页返回、401、403 等必须归类。
3. 自动重登不能无限高频重试。
4. 遇到风控、验证码、403 等阻断类错误时进入退避，并给管理员告警。
5. 下注失败后才执行账号自检，不在下注前重复拉倒计时。
6. 结算分支也必须使用同一套重登恢复链路。

前端提示：

- `账号会话异常，系统正在重连。日志编号：SESSION-001。`
- `账号重连失败，请联系管理员处理。日志编号：SESSION-002。`

## 10. 告警中文提示和日志编号规则

原则：

1. 操作者端只展示简短中文和日志编号。
2. 后端日志记录详细过程、接口、原始返回、账号、策略、期号。
3. 状态变化才弹窗，持续状态不重复弹窗。
4. `draw_pending` 和 `draw_wait_retry` 是过程状态，不作为失败告警。

建议编号：

| 编号 | 操作者提示 |
| --- | --- |
| `SHARED-002` | 数据更新变慢，可能影响投注，请联系管理员处理。 |
| `DRAW-001` | 开奖数据暂未获取，10秒后再次刷新。 |
| `MARKET-001` | 当前处于停盘。 |
| `BET-001` | 本期下注已跳过，数据状态异常。 |
| `BET-002` | 当前策略过多，可能引发风控导致下注失败。 |
| `SESSION-001` | 账号会话异常，系统正在重连。 |
| `SESSION-002` | 账号重连失败，请联系管理员处理。 |
| `SETTLE-001` | 订单结算中，请稍后查看。 |
| `SETTLE-002` | 结算数据暂未返回，系统将继续补偿。 |
| `SETTLE-003` | 结算失败，请联系管理员处理。 |

管理员日志必须包含：

1. 操作者账号。
2. 第三方账号。
3. 平台类型和链接。
4. 策略 ID。
5. 期号。
6. 请求阶段。
7. 平台原始返回摘要。
8. 重试次数和下一次重试时间。

## 11. 并发锁、串行锁、频率限制

共享采集锁：

1. 同一 `shared_group_id` 同一时间只能有一个平台采集请求。
2. 开奖专项刷新期间，普通 25 秒采集跳过或顺延。
3. 管理员手动检测不能打断开奖专项刷新。

worker 锁：

1. 同一第三方账号、同一平台类型只能有一个真实下注 worker。
2. worker 锁按账号和平台维度续约。
3. 失锁必须停止当前 worker 并告警。

session 锁：

1. 同一账号登录串行。
2. 同一账号平台请求串行。
3. 同一账号恢复重登串行。

结算锁：

1. 同一第三方账号结算请求串行。
2. 多策略同账号结算按账号聚合，不按策略并发。
3. 多账号可轻微错峰。

频率限制：

1. 共享普通采集：25 秒。
2. 共享开奖专项刷新：10/10/10/5/3/1，之后 10 秒。
3. worker 本地回退：最多 80 秒一次。
4. 心跳：10 秒一次。
5. 结算：开奖归零后 20 秒首取，后续 10/5/8/10 秒。

## 12. 幂等结算和重启恢复

幂等键：

建议按以下组合保证唯一：

1. `account_id`
2. `platform_type`
3. `issue`
4. `order_id` 或本地投注记录 ID

幂等规则：

1. 已结算订单不能重复累计盈亏。
2. 重试返回相同订单时，只允许补充缺失字段。
3. 状态流转必须可追踪。
4. 补偿结算不能覆盖已经人工修复的数据。

重启恢复：

1. 启动时清理旧 worker 锁。
2. 恢复共享采集器。
3. 恢复 running 策略的 worker。
4. 恢复未完成结算任务。
5. 不因 `verification_stale` 跳过 running 策略恢复。
6. 恢复后先处理待结算，再进入正常下注循环，但结算不能长期阻塞下注。

## 13. 回归测试方案

后端单元测试：

1. 共享采集器 25 秒普通采集。
2. 开奖专项刷新状态机。
3. `draw_pending` 不触发 worker 本地回退。
4. `shared_error` 触发 80 秒低频回退。
5. 本地回退不写共享池。
6. worker 下注前不调用 `adapter.get_current_install()`。
7. 快照过期时跳过下注并产生中文提示。
8. 结算分支 20/10/5/8/10 秒退避。
9. 10 分钟内保持 `settlement_pending`。
10. 重启恢复不受 `verification_stale` 阻断。

后端集成测试：

1. 共享账号正常，多 worker 只读共享快照。
2. 共享账号掉线，worker 低频回退并提示 `SHARED-002`。
3. 平台停盘，worker 停止新下注但继续结算。
4. 账号被顶，worker 自动重登后继续执行。
5. 多策略同账号，下注错峰，结算聚合。

前端测试：

1. 封盘倒计时为 0 显示封盘中。
2. 封盘和开奖倒计时都为 0 显示等待开奖。
3. `draw_wait_retry` 显示开奖数据暂未获取。
4. `market_closed` 显示当前处于停盘。
5. `SHARED-002` 使用弹窗展示。
6. 前端不再固定开奖后 30 秒刷新。

端到端测试：

1. 启动共享账号，前端看到期号和倒计时。
2. 创建真实策略，确认下注前没有额外倒计时平台请求。
3. 观察 3 期，验证下注、结算、告警、前端展示。
4. 中途断开共享账号，验证 worker 低频回退和前端提示。
5. 重启服务，验证 running 策略和待结算恢复。

## 14. 不能改动的边界

第一阶段禁止改动：

1. 不修改策略选号算法。
2. 不修改马丁序列计算规则。
3. 不修改平注、马丁、AI 推荐策略的业务含义。
4. 不调整赔率计算逻辑。
5. 不引入新的投注平台适配器。
6. 不删除既有投注记录、结算记录、盈亏记录。
7. 不修改管理员授权策略的大方向。
8. 不修改第三方账号绑定表的核心含义。
9. 不让 worker 本地回退数据写回共享池。
10. 不恢复下注前第三方倒计时强校验。
11. 不把 `draw_pending` 或 `draw_wait_retry` 当成失败告警。
12. 不把结算失败提前扩大成策略停止。
13. 不做服务器部署、数据库清理或生产重启。

遇到阻塞时的处理：

1. 如果现有表结构无法承载字段契约，先上报需要迁移的字段，不自行改表。
2. 如果现有 worker 主循环无法安全拆分结算，先上报最小拆分点。
3. 如果平台返回错误样本不足，先记录未知错误，不强行归类。
4. 如果改动会影响真实下注安全，停止执行并上报。
