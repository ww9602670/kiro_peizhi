# 轻量 UI 运行状态与自动回房需求

## 背景

当前轻量 UI 已能完成账号登录、接管大厅、选择房间和发送进房命令，但实测出现以下问题：

1. 账号进入房间后，倒计时、局号、余额和状态机没有持续更新。
2. 卡片只显示“房间已打开”等进房结果，不足以判断账号是否仍在真实游戏房间。
3. 账号长时间不下注被平台踢回大厅后，轻量 UI 不会自动补进房。
4. 新版 UI 不能为了显示状态，把旧 UI 的高频刷新和大量诊断面板整套搬入。

## 目标

1. 轻量 UI 能显示每个账号的房间、局号、倒计时、余额、状态机摘要和数据新鲜度。
2. 轻量 UI 使用已有 worker 的低频 runtime 状态源，不改采集算法、不改坐标、不改真实下注前保护。
3. 当账号从房间掉回大厅时，在满足冷却和房间号已知的前提下，自动发送一次进房命令。
4. 自动回房过程要有简短日志，避免静默失败。

## 非目标

1. 不重写旧 UI 的完整状态面板。
2. 不修改 `cluster_process_worker.py` 里已验证的进房点击、坐标、倒计时、局号、余额和下注前 preflight 核心逻辑。
3. 不开启 canvas 探针作为常态资源消耗。
4. 不在状态缺失时强行下注。

## 验收标准

1. 账号卡片能显示状态机摘要，例如“下注中 / 等待 / 房间已打开 / 数据过期”。
2. 收到 worker state 事件后，卡片显示局号、倒计时、余额。
3. 没有新 state 事件时，倒计时按本地时间自然递减，过期后显示“数据过期”。
4. 收到大厅态且该账号已被要求进房时，控制器自动重发进房命令，但同账号有冷却限制。
5. 单元测试覆盖状态映射、倒计时递减、自动回房冷却和 runtime scan 配置。
6. 轻量测试全部通过后再重启 UI。
